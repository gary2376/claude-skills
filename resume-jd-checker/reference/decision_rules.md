# Skill 決策規則(固定套用,不要跟使用者呈現「有兩派看法」)

來源：resume-rubric.md 第三節，使用者已拍板決策。

## 1. 照片
- 外商 → 建議拿掉照片
- 台商 → 中性，不強制
- 精簡/一頁型排版 → 一律建議拿掉
- 例外：空服員/航空業 JD → 跳過本規則，照片是審查關鍵，應保留

## 2. 頁數
- 預設一律建議壓在一頁，不分資歷
- 例外：學術 CV（沒有頁數上限）不適用

## 3. 格式
- 建議「技能摘要前置 + 時間序經歷佐證」的混合格式（hybrid format）
- 不要建議完全拿掉時間軸的純技能導向格式（會被質疑在隱藏問題）
- 例外：自由工作者/接案（freelancer）本來就沒有連續雇主時間軸，純技能導向格式可以

## 4. 自傳/Objective Statement
- 預設建議拿掉或精簡成一行 Professional Summary
- 若投遞對象是台灣傳產/公家單位，提醒「本地慣例可能期待自傳，但建議精簡到最必要」，不要完全不提
- 例外：空服員/航空業 → 自傳是面試發問依據，非常重要，不適用本規則

## 5. AI 用語偵測
- 掃描履歷內文，命中 `reference/ai_tell_words.json` 清單詞彙即標記
- 判斷輔助原則：一句話拿掉品牌/專有名詞後仍放諸四海皆準，視為空話，優先標記
- 建議：命中時提示使用者改寫成更具體、口語化、能被數字/情境佐證的敘述

## 6. 包裝程度
- 允許使用更有力的動詞/句型包裝經歷（例：「參與專案」→「主導專案」），前提描述屬實
- 可驗證性檢查：每條經歷 bullet 至少包含「動作＋可衡量結果」之一有具體數字/情境
- 只有形容詞、沒有可驗證內容的句子（例如「具備優秀溝通能力」）視為包裝過度但缺乏支撐，建議補上實例
- 沒有硬數字時的替代量化維度（來自第八節補充）：服務對象層級（C-level/regional）、範圍（multi-team/multi-country）、頻率（weekly/ongoing）

## 通用量化公式（第一節，寫建議時可直接套用）
「用 [方法] 做了 [動作]，達成 [可衡量結果]」

## Experience 黃金結構（第八節補充）
Action 動詞 + 核心職責 + 工具/方法 + 成果 —— 「工具/方法」建議明確點名（例如「用 SQL」「用 Jira」），不要籠統帶過。

## 7. 引用依據（找到對應時附上，增加建議可信度）
給建議時，若命中以下常見錯誤類型，附上依據來源（來自 `full-research-rubric.md` 第四、五節），不要每次重讀整份文件，直接查這張表：

| 命中情況 | 依據來源 |
|---|---|
| 只有形容詞、沒有可驗證內容（例：「樂觀開朗、勤勞務實」） | ⭐ 104職場力《10大常見NG錯誤》— 用形容詞代替具體事實；Grant Cardone — 履歷要寫「你親自推動了什麼」而非職責清單 |
| 只列職責、沒列成果（例：「擺盤，準備食材」） | TopResume《Top 10 Resume Mistakes》；⭐ Gayle Laakmann McDowell《The Google Resume》量化公式 |
| 弱動詞開頭（I helped / 負責） | ⭐ Google 前招募官建議 |
| 自傳/自我介紹與應徵職務無關 | ⭐ 經理人雜誌《5成沒自傳、36%沒照片》 |
| 建議一頁、拿掉冗長細節 | Goldman Sachs / McKinsey 招募資訊 — 一頁原則；⭐ Richard N. Bolles《What Color Is Your Parachute?》— 8秒瀏覽法則 |
| 內容包裝過度、缺乏可驗證細節 | Elon Musk —「不要只看履歷，要看對話」，履歷內容要撐得住後續驗證 |
| 錯字/格式明顯錯誤（如信箱格式錯） | 不用引用權威來源，這是客觀事實錯誤，直接指出即可，硬掛引用是過度包裝 |

引用時格式：「這是 [具體問題] —— 依據 [人物/機構]：[核心主張]」，不要整段複製來源介紹，一句話帶過就好。找不到對應的，不要硬套引用湊數。
